## 1. 风格画像

非营利研究社区的知识出口：用学术论文的体裁纪律 + 工程实践的数字精确癖 + 人文立场的行动性收尾，生产"可核验的研究输出"。受众契约：读者被默认具备工程与 AI 领域背景，要求信息增量与信源透明，不接受情绪化渲染。
⚑ 例证："匿名上线、全网实测、择日揭晓"（GLM-5.3-Flash 报告——用事实节奏替代形容词）

## 3. 结构模板（按体裁，来自语步标注）

| 体裁 | 典型语步序列 | 收尾形态 |
|---|---|---|
| **报告体** | 元信息头 → 摘要 → 编号章节（概述→发布策略→规格→评测→定价→竞争→挑战→总结）| 编号结论 + 后续关注问题清单 |
| **期刊体** | 引言 → 理论基础 → 分层论证（微观→中观→宏观）→ 结论与讨论 | 开放问题 + 研究议程 |
| **行业分析** | HOOK（场景并置）→ CONTEXT+ARGUE（数据锚定）→ FRAME（明示 N 问题）→ ARGUE/COUNTER 交替 → APPLY（判断标准）→ CLOSE（展望+系列预告）| 展望 + 信源征集 |
| **博客体** | 现象层 → 机制层 → 处方层 → 诊断层 → 决策层（功能分层命名）| 方法推广句 / 可检验赌注 |

叙事-分析配比（FDE 篇实测）：全篇 ≈0.25，起源/场景节高（0.5–0.9），论证节归零——叙事严格服务于概念解释。

## 4. 论证规范

- 证据配比：evidence_per_claim ≈ 1.8（FDE 篇实测）
- 信源层级：third-party 44% / community 44% / official 11%——官方口径作锚点，从业者社区作血肉
- 限定语习惯：结论必带边界（⚑"大多数跟风效仿者""三种值得认真对待""缺任意一项就足以导致失败"）
- 反驳处理：must-have 模块——质疑须显式列出，并区分处理结果（rebutted / left-open 如实标注，未解决的不装作已解决）
- 判断句置信表达："据报道/官方口径/仍建议以官方为准"；断言型绝对化 1.05/千字 vs 限定语 3.12/千字——克制比 ≈ 1:3（期刊体最克制 0.55，博客体叙事段最放开 2.16）。词表修复后 v10 口径：1.08 vs 2.69 ≈ 1:2.5，序不变

## 5. 用词与语言

- 高频概念词：可证伪、约束、闭环、涌现、对齐、门禁、机制、框架（与个人知识库 Cards 词表同源）
- 术语纪律：中英混排、首现括注（⚑"前沿部署工程师（FDE）"）——**但现状不达标**：FDE 一文出现 5+ 种译法 + "全磁盘加密"误译，术语一致性表是发布前强制检查项
- 比喻系统：允许且鼓励全文复用单一比喻（修路/壳/笼子/裁判），比喻服务概念而非情绪

## 7. 发布前自检清单（模式二 · 双模式闭环）

1. 统计层跑分：感叹号=0、emoji=0、限定语 ≥2.5/千字（报告体 ≥6，2026-09-07 词表修复后 v10 口径）、句长 ≤36 字均值
2. 术语一致性：文内同一概念唯一译名（对照术语表）
3. 段落去重：语步标注核查 CLOSE 区无重复段（FDE 篇教训：para 36）
4. 反驳模块：行业分析/报告体必须含 COUNTER 节，且 rebuttal resolution 如实标注
5. 参考来源：期刊体 GB/T 格式 ≥8 条；报告体分层附录（已核实/修订澄清/待确认）
