# 重写稿质量根因分析与语言规范优化方案（2026-09-14）

> 触发：两篇生产级重写（30k-bookmark / judgment）经主编评判"语言不如原稿"。
> 证据：四篇文本全读 + profiler 定量对照 + v1→v3 盲测迭代链 + 两个写作子代理的执行简报。
> 结论先行：**重写稿的缺陷不是执行失误，而是规范本身的四层错配——测量层目标错配、约束语义错配、重写协议错配、体裁映射未验证。**

## 二、根因分析（四层）

### 1. 测量层：代理目标替代了真实目标（Goodhart 定律实例）

§0.2 走廊优化的是"与 anthropic/openai 博客的相似度"，而真实目标是"可读的研究性写作"。两家参照库以机构 build-log 为主（we 叙事、高 hedge 是其**内容**决定的：工程不确定性陈述多），把它们的词汇预算（hedge ≈10、人称 ≈40、克制比 4–5:1）套到分析评述体裁上，写作端为"贴目标"只能**加 hedge、加 we、加 scaffold**——原稿的果断语气（克制比 1.6–1.7）不是缺陷，是体裁属性。

**关键证据**：原稿本身就是主编认可的好文章，而其 hedge/人称/克制比全部低于走廊。这证明走廊目标对该体裁是错的，不是"原稿不达标"。

**更深层**：v1→v3 盲测没暴露这一点，因为三轮盲测题材恰好是 we 叙事的工程复盘（与参照库同体裁），走廊在同体裁上自洽、跨体裁失真。盲测的体裁覆盖不足是方法论缺口。

### 2. 约束语义层："目标值"语义错误——预算应是护栏，不是靶心

走廊表以"目标值 ≈X + 区间"表达，写作端自然把区间中点当靶子打（"贴目标下沿/中段"字样充斥自验）。但风格指标的正确语义大多是**单侧护栏**：

- 句长/段长/P90：上限约束（防长句难读），越短越好的一侧不该有奖
- hedge/克制比：上限约束（防犹豫雾），不存在"hedge 不足"
- 人称/设问：宽松区间即可，无目标值
- 感叹号：红线（已是单侧）

把 hedge 设成"目标 ≈10"等于要求文章必须犹豫到某个程度——这在语义上就不成立。

### 3. 重写协议层：生成式重写丢失了原稿的句级工艺

本次执行的是"提取论点骨架 → 按 playbook 重新生成"。原稿的警句、节奏、措辞选择是**句级资产**，重新生成必然重写每一句话——好句子被平均化，坏句子被引入（语法错误、成语误用）。对重写任务，正确协议是**编辑式**：以原稿句子为底，最小干预地做手术（拆长句、补承接、加结构件），原样保留已达质量线的句子。生成式只适用于全新成稿。

同时"信息不得丢失 + 必须命中预算"双约束的唯一解是膨胀（+40%），而膨胀本身就是稀释。重写任务缺一条**篇幅膨胀率护栏**（建议 ≤+15%）。

### 4. 体裁映射层：中文骨架直搬英文，未经体裁内验证

行业分析骨架（场景 HOOK + COUNTER 独立节 + 系列预告收尾）标注自中文语料（fde-role-renaissance 单篇），其在英文分析文中的适配性从未被验证过。v3 盲测验证的是博客体骨架 × 工程复盘题材一个格子；本次生产使用落在行业分析骨架 × 文献评述题材另一个格子——**每个格子都需要自己的首次验证**，通用骨架"兜底"的说法掩盖了这一点。

### 附：执行层的两个次要因素（非根因但放大缺陷）

- **约束过载**：13 项走廊 + 7 条处方 + 5 条签名 + 保真约束同时压在一次生成里，写作带宽被指标占满，惯用语控制降级（语法错误由此而生）。人类编辑流程是分趟的（结构→论证→语言打磨），当前协议没有分趟。
- **术语纪律过界**：术语唯一与 MATTR 压带共同导致同义归一过度（12 处单例词归一、"the record we read"×6）——"术语"的适用范围应限于**已命名概念**，不应覆盖普通短语。

## 三、语言规范优化方案（playbook 修订清单）

按治本程度排序：

### P0-1 用自有英文样本建统计层，替代处方走廊（治本）

主编的 vault 中已有通过人工质量线的英文文章（本次两篇原稿即样本：hedge ≈5、克制比 ≈1.6–1.7、人称 ≈2–3、段长 55–56、MATTR 0.73–0.75、P90 41–42）。**处方走廊的本意就是"自有英文语料缺位时的过渡"（§8 缺口 7）——现在语料有了。**

行动：采集 vault 中 EN-* 文章（质量线以上）入 `corpus/kezhongke-en/`（建议 ≥5 篇）→ profiler 出基线 → §0.2 处方走廊降级为对照组，英文预算以自有统计层为准。注意隐私分级（vault internal 内容不入 public repo，语料沿用"全文不入库"政策，仅 JSON 入 output/）。

### P0-2 预算语义从"目标值"改"护栏"（治本，立即可做）

§0.2 走廊表改写为三栏：**红线（单侧）/ 参考区间（无目标值）/ 记录项（只记录不判定）**。逐项重定性：
- hedge：区间 [5, 13.5]，删目标值——低于 5 不判失（果断是体裁权利）
- 克制比：红线 <1.5:1（防鲁莽），删除 4–5:1 典型带（防犹豫雾靠 hedge 上限已够）
- 人称：区间 [0, 69]，删 ≈40 目标
- 句长/P90/段长：维持上限语义，明确"无下限奖励"
- 数密：分析类题材只记录不判定（题材决定密度）

### P0-3 重写协议与生成协议分离（治本，立即可做）

playbook 新增"重写任务"分支：
1. **编辑式重写**：以原稿为底做最小干预手术——只允许五类编辑动作（拆长句/补承接/加结构件/术语归一/删冗余），其余句子原样保留；禁止整段重造
2. **篇幅膨胀率护栏**：重写稿篇幅 ≤ 原稿 ×1.15
3. **句级资产清单**：动笔前先标出原稿的警句/金句（aphorism），重写后逐一核对存活
4. 生成式（从骨架新写）仅限无原稿的新稿任务

### P1-4 处方 7 修正：承接的"信息性"要求

补两款：①指针句必须携带新信息（预告内容而非预告结构；"section one answers…"式纯结构预告禁用）；②显式承接装置仅在内容顺序本身不足以承载逻辑时使用——隐式逻辑优先，显式装置是补救不是义务。

### P1-5 口头禅检查（写作端自检新增）

任何 ≥4 词的非术语短语全文出现 ≥3 次，须证成（是命名概念）或改写变体。"the record we read"×6 即此类。

### P1-6 语言打磨独立成趟（fluency pass）

协议分趟：第一趟结构/论证，第二趟指标校验，**第三趟语言打磨（指标盲）**——只读语言流畅度，不看任何数字（防指标回灌）。语法/成语/节奏在此趟修复。对应人类编辑的 copyedit 环节。

### P2-7 体裁×语种矩阵的验证覆盖登记

playbook 每个"骨架 × 语种 × 题材"格子登记验证状态（已验证/未验证），未验证格子的成稿必须标注并走人工复核——替代当前"通用骨架兜底"的笼统说法。
