## 摘要

GLM-5.3 是智谱 AI 于 2026 年 8 月 14 日正式发布的新一代大模型，官方标题为《GLM-5.3: Frontier Coding with Emergent Cyber Capabilities》，核心亮点可概括为“**前沿编程能力 + 涌现式网络安全能力**”。

本报告需要首先明确的关键事实是：GLM-5.3 使用与 GLM-5.2 **完全相同的基座模型**，本次能力提升全部来自**后训练阶段的规模化扩展**，而非重新训练底座或扩大参数规模。官方原文明确写道：“It uses the same base model as GLM-5.2 — every gain comes from post-training.”

在性能层面，GLM-5.3 成为当前最强的开源权重编程模型之一，Z.ai Code Bench 较 GLM-5.2 提升 50%，并在 Terminal Bench 3.0、Agents’ Last Exam 等公开基准上取得开源 SOTA。更值得关注的是，模型在后训练过程中涌现出了超出预期的网络安全能力，已在真实代码库中发现 2436 个漏洞，其中包含 1097 个中高危问题。

模型权重计划在发布两周后开放。API 已于 8 月 19 日全面开放，可配合 ZCode、Claude Code、OpenCode 等编程 Agent 工具使用。

## 一、概述

### 1.1 发布背景

GLM-5.3 是继 GLM-5.2 之后的又一次重要迭代，官方博客标题《GLM-5.3: Frontier Coding with Emergent Cyber Capabilities》直译为“前沿编程能力与涌现式网络安全能力”，精准概括了本次升级的两大核心方向。

### 1.2 两大核心升级

1. **更强的编程能力**：GLM-5.3 是当前最强的开源权重编程模型之一，在智谱内部 Z.ai Code Bench 上相比 GLM-5.2 提升 50%，并在 Terminal Bench 3.0、Agents’ Last Exam 等公开基准上取得开源 SOTA。
2. **涌现式网络安全能力**：在后训练规模化过程中，模型的网络安全能力（漏洞发现、漏洞利用推理）出现超出预期的增长，在 CyberGym 漏洞发现基准上取得 SOTA，且在利用链越靠后的环节，相比 GLM-5.2 的提升幅度越大。

### 1.3 开源与使用状态

- **模型权重**：官方说明将在正式发布后两周内开源，原因是需要完成安全评估与加固（safety evaluation and hardening）。按发布时间推算，预计为 2026 年 8 月 28 日左右。
- **API**：已于 2026 年 8 月 19 日全面开放。
- **工具接入**：已可在 ZCode、Claude Code、OpenCode 等主流编程 Agent 工具中直接使用。

## 二、模型底座与技术路径：全部来自后训练规模化

### 2.1 与 GLM-5.2 共享同一基座

官方原文明确指出：“It uses the same base model as GLM-5.2 — every gain comes from post-training.” 这意味着 GLM-5.3 并非架构或预训练层面的换代，而是通过后训练技术栈的持续投入实现能力跃升。

智谱在 GLM-5.2 阶段搭建的三大技术底座被延续并进一步扩大规模：

- **IndexShare**：用于高效长上下文处理的注意力索引技术。
- **SAO（Sequential Advantage Optimization，长时程强化学习策略）**：结合压缩（compaction）机制，用于长时程任务上的强化学习训练，使 GLM-5.3 在长上下文 / 长时程任务上的增益不会随任务变长而衰减。
- **slime**：智谱自研的大规模异步训练框架。

过去一个月，智谱在这套技术栈上持续扩大规模：更多训练环境、更多样化的任务、更多训练计算量投入。

### 2.2 训练环境合成：从“编程练习”走向“真实专业工作”

GLM-5.3 后训练的核心方法论转变，是把训练环境从“看起来像编程练习”的任务，转向更贴近真实专业工作流程的任务。部分环境的任务复杂度相当于资深工程师数天的工作量。

以 ML 基础设施类任务为例，模型会被赋予与真实工程师相同的工作环境，包括访问计算集群、存储系统、内部文档、代码库和实验结果，要求模型自主诊断训练栈中的性能瓶颈、实现优化方案、运行实验，并交付可衡量的端到端加速效果，同时保证正确性。这类训练推动模型走向“端到端独立承担大型任务”，而非依赖用户逐步拆解与监督。

为规模化生成这类环境，智谱构建了自动化流水线：

- **研究型 Agent** 从真实工作中收集任务模式，将其转化为具有多步依赖和隐藏状态的可执行长时程环境。
- **裁判 Agent（judge agent）** 尝试解答每个任务，以验证其确实可解。
- **验证器（verifier）** 在不接触参考答案的情况下被合成出来，同时利用求解轨迹发现并修复“奖励捷径”（reward shortcuts，即模型钻营取巧刷分的漏洞）。
- 通过 oracle 检查、no-op 检查和未解状态检查三重验证的验证器，才能产出足够可靠、可直接用于训练的二元奖励信号。

官方同时指出，该流水线目前仍需要相当程度的人工参与，让环境生成与验证过程更自主化是下一步重点方向。

### 3.2 Z.ai Code Bench：内部真实场景基准

由于公开基准存在污染风险，智谱同步推出内部专有基准 **Z.ai Code Bench**，将 Agent 置于复杂本地开发环境中，从“端到端任务完成率”和“细粒度清单准确率”两个维度评测。

结果显示，GLM-5.3 相比 GLM-5.2 在每个思考强度档位均取得更强表现，且消耗更少输出 Token：

- **Max 强度**：GLM-5.3 达到 34.5% 完成率，约消耗 7.5 万输出 Token；GLM-5.2 为 23.4%，消耗 9.6 万 Token。
- **High 强度**：GLM-5.3 达到 31.4%，约消耗 5 万 Token，超越 Claude Opus 4.8（29.5%，消耗 12 万 Token）。
- GLM-5.3 仍落后于 Claude Fable 5（Max 强度下 39.5%）。

这说明 GLM-5.3 在性能与 Token 效率的平衡上取得显著进步，但距离最顶尖闭源模型仍有差距。

## 四、涌现式网络安全能力：本次发布最大亮点

### 4.1 能力涌现的发现过程

智谱在后训练数据中引入漏洞发现相关数据和环境，目的是提升模型对漏洞的识别与推理能力。但训练过程中出现超出预期的现象：随着训练规模扩大，模型网络安全能力增长速度远超预期。GLM-5.3 不仅能识别孤立漏洞点，还开始能够跨多个利用阶段进行推理，形成完整且连贯的利用链（exploitation chain）规划。

### 4.2 三项基准的分层验证

官方在三个覆盖不同阶段的安全基准上进行了评测：

- **CyberGym**（白盒源码起点，测试漏洞识别与触发验证）：GLM-5.3 得分 84.5%，GLM-5.2 为 77.2%，为该基准当前最优成绩，超过 Mythos 5（83.8%）和 GPT-5.6 Sol（83.6%）。
- **ExploitBench**（要求对真实漏洞及其利用进行更深层推理）：GLM-5.3 达到 54.4%，相比 GLM-5.2 的 24.4% 翻倍以上；但 Mythos 5 与 GPT-5.6 Sol 分别达到 78.0% 和 76.5%，闭源模型仍明显领先。
- **ExploitGym**（衡量时间归一化预算下能完成多少利用任务）：GLM-5.3 在 2 小时 / 6 小时预算内分别完成 105 / 130 个任务，相比 GLM-5.2 的 29 / 39 大幅提升；Mythos 5 达到 181 / 247，仍保持领先。

三项基准呈现一致规律：**在利用链越靠后的环节，GLM-5.3 相比 GLM-5.2 的提升幅度越大，但与闭源前沿模型的差距也越大**——即能力增长最快的地方，恰恰是当前落后最多的地方。

### 4.3 真实世界验证：269 个项目、2436 个漏洞

智谱进一步测试了这些能力能否迁移到真实场景。自 GLM-5.2 起，智谱已与中国多家安全团队合作，让模型对真实代码库进行漏洞挖掘。经专家评审、筛选与去重后，模型在 **269 个项目**中识别出 **2436 个漏洞**，其中包含 **1097 个中高危问题**。发现覆盖系统内核、操作系统、浏览器引擎、开源基础设施、Web 应用和网络协议等领域，许多漏洞已存在数年甚至数十年，最早的漏洞可追溯至 1981 年，平均每个漏洞在被发现前潜伏约 26.6 年。

| 指标 | 数值 |
|---|---|
| 追踪到的发现总数 | 2,436 |
| 已公开披露 | 53 |
| 仍在保密期（under embargo） | 2,383 |
| 严重（Critical） | 107 |
| 高危（High） | 990 |
| 中危（Medium） | 1,286 |
| 低危（Low） | 53 |

| 影响年限跨度 | 45 年（1981–2026） |

基于这些发现，智谱建立了 **Z.ai Security Disclosure Ledger**（安全披露公开记录平台），持续更新已披露与仍处保密期的漏洞记录，包括受影响项目、严重程度、CVE 编号（如有）及漏洞存续时间等信息。

## 五、slime 训练框架：支撑长时程 RL 规模化的基础设施

GLM-5.3 的全部训练运行在智谱开源的后训练框架 **slime** 之上，训练侧基于 Megatron，rollout 侧基于 SGLang。其设计理念是将训练、rollout 与数据缓冲统一在单一数据流中，使数学、代码、沙箱、验证器和长时程 Agent 环境都能以“数据生成”方式接入，而无需改动训练主循环。

本次针对 slime 的改进集中在两方面：

**算法侧**：

- 新增 top-p mask、top-k 与全词表 OPD（On-Policy Distillation）等面向 RL 研究的能力。
- 提升训练-rollout 一致性，包括 R3 风格设置和训练 / rollout 路径的完全数值对齐。
- 训练-rollout 一致性评估中的平均 logprob 差异被控制在 **1e-7 量级**，相比此前设置减少超过 99.99%。

**系统效率侧**：

- 引入本地存储作为额外缓存层，分层存储原本占用主机内存的模型状态和数据。
- 针对多教师 OPD，通过动态教师切换与预取，无需为每个教师单独搭建长期运行的推理服务即可使用多个教师模型，显著降低资源消耗。
- 改进路由器与 slime 之间的联合调度与负载均衡，使不同长度和完成时间的 rollout 请求更充分利用推理资源。
- 综合系统级优化，长时程编程 RL 任务的端到端训练吞吐量提升超过 **2.3 倍**。

## 六、API 与产品生态

### 6.1 API 变更：不再支持关闭思考模式

GLM-5.3 支持三档思考强度：

- **low**：轻量思考。
- **high**：增强思考。
- **max**：深度思考，推荐用于编程任务。

GLM-5.3 **不再支持完全关闭思考（disabled）**。若既有应用使用 `thinking.type: "disabled"`，升级到 glm-5.3 前必须改为 `enabled` 并设置 `reasoning_effort: "low"`，否则请求将失败。

```json
{
  "model": "glm-5.3",
  "thinking": { "type": "enabled" },
  "reasoning_effort": "max"
}
```

### 6.2 编程工具生态与 GLM Coding Plan

GLM-5.3 已可在 ZCode、Claude Code、OpenCode 等主流编程 Agent 工具中直接使用。对 GLM Coding Plan 订阅用户，智谱已将全体用户升级到 GLM-5.3，并推出按积分（points）计量的配额体系——输入、缓存输入与输出 Token 分别计算积分。非高峰时段调用只消耗标准积分的 50%；高峰时段为北京时间周一至周五 14:00–18:00，其余时段包括周末均享 5 折。

配合 ZCode 使用还有以下权益：

- **缓存命中率超过 98%**：重复上下文按更低缓存价率计费，有效 Token 利用率提升约 30%。
- **限时 1.5 倍配额加成**：与缓存节省叠加，8 月 31 日前最高可达标准配额的 180%。
- **Goal 模式**：长时程任务自动规划、编码、测试与验证，直至达成目标。
- **远程控制**：可通过企业微信或飞书在手机端监控与操控长时间运行的任务。

### 6.3 模型权重开放计划

GLM-5.3 的模型权重计划在发布两周后公开放出，预计为 2026 年 8 月 28 日左右，届时可支持本地部署。API 已于 8 月 19 日全面开放。官方给出的延迟开源理由是完成安全评估与加固流程。

## 七、总结与展望

### 7.1 核心结论

1. **GLM-5.3 已正式发布并开放 API 使用**，模型权重预计在两周后开源。
2. **本次升级是纯后训练规模化的成果**，与 GLM-5.2 共享相同基座模型，并非参数规模跃升；核心投入方向是训练环境的规模化、多样化与真实工作场景化。
3. **编程能力是最直接的提升点**：Z.ai Code Bench 提升 50%，多项公开基准取得开源 SOTA 或大幅进步，Token 效率同步提升。
4. **涌现式网络安全能力是本次最具话题性的发现**：模型在漏洞发现与利用链推理上的能力增长超出研发预期，并已在真实代码库中发现 2436 个漏洞（含 1097 个中高危）。这带来切实防御价值，也意味着双重用途风险需要持续关注，解释了官方推迟两周开源权重、留出安全评估与加固窗口的原因。
5. **与闭源前沿模型相比仍有差距**：在网络安全利用链的深层环节（ExploitBench、ExploitGym）与 Fable 5、Mythos 5、GPT-5.6 Sol 等模型相比差距依然明显；但差距正在缩小，部分基准已取得局部领先。

### 7.2 后续关注问题

- 权重开源后是否会同步公布更详细的模型卡片与安全评估报告。
- 智谱是否会将涌现式网络安全能力产品化，例如集成到安全审计类产品线。
- Z.ai Security Disclosure Ledger 的后续披露节奏，以及 2383 个保密期漏洞的处理进展。
- GLM-5.3 是否会像 GLM-5.2 一样接受第三方安全机构的独立风险评估，并同步加强防御机制。
