**可迁移（语言无关，英文成稿照常作硬约束）**：

- 收尾形态与操作化招式（§6–§7）：明示 N 问题清单、信源分层标注、判断带边界、编号结论+开放问题、单一比喻复用；

**弱迁移（次数类，有长度依赖，英文成稿作参考区间）**：设问 1–4 次/篇、第一人称 1–13 次/篇、客观自指（英文对应 this essay/this analysis）1–5 次/篇。

## 2. 通用语步骨架（HOOK/FRAME/CONTEXT/ARGUE/COUNTER/APPLY/CLOSE）

[标注-3篇] 基于 fde-role-renaissance（38 段）+ glm-5-3-analysis（48 段）+ multi-agent-sociology（45 段）共 131 段标注聚合；ARGUE 占比 64%，COUNTER 7 处全部来自行业分析篇，HOOK 全库仅 1 例，叙事段占比 12%。

```
HOOK（可选，仅行业分析用场景并置；报告体/期刊体禁止，以元信息头/摘要替代）
→ FRAME（必选项一：元信息头+摘要 / 摘要+关键词 / "本文解答 N 个问题"清单——开场必有框架性预告）
→ CONTEXT（概念定义、事件背景、历史叙事；叙事只允许出现在这里，叙事比 0.3–0.6）
→ ARGUE×n（主体 ≈2/3 篇幅；数据锚定 / 官方口径引用 / 多方引语对比 / 机制分析推进）
→ COUNTER（行业分析必备独立反驳节；报告体以"局限声明/口径澄清"内化；期刊体以"局限声明"收尾前置）
→ APPLY（判断标准清单 / 操作判据，如"四项标准，缺一即败"）
→ CLOSE（编号结论 + 展望 / 后续问题清单 / 局限声明+研究议程 / 系列预告+信源征集）
```

写作指令：
1. 开场三段内必须完成"框架预告"——告诉读者本文解答几个问题、分几层展开（实证：FRAME×5 连排是报告体开场指纹）。
2. ARGUE 段落每个论断挂证据（实证配比 evidence_per_claim = 1.8，见 §5）；叙事段落压到起源/场景节内，论证节叙事比归零。
3. 反驳显式列出并标注处理结果（rebutted / left-open），未解决的不装作已解决。
4. 小节结尾允许比喻回收（"修路队就会收缩，但修路不会结束"），全文 CLOSE 区禁止重复段（FDE 篇 para 36 教训）。

## 3. 分体裁骨架（已实证部分）

[标注-3篇]

## 5. 论证与信源规范

[标注-1篇] 论证层标注仅 fde-role-renaissance.argument.json 一篇——**单篇外推，指导写作前建议补标至 ≥3 篇**。以下数字仅作起步默认值。

- 证据配比：evidence_per_claim ≈ 1.8（5 主张 / 9 证据）。写作指令：每个 level-1 主张至少挂 2 条不同类型证据（数据 + 案例/引语）。
- 信源层级：third-party 44% / community 44% / official 11%。官方口径作锚点（JD、官方博客原文），从业者社区作血肉（复盘、追踪、X 帖）；转述必标信源属性（"据报道""官方口径""仍建议以官方为准"）。
- 限定语纪律：结论句必带边界——"大多数跟风效仿者""三种值得认真对待""缺任意一项就足以导致失败"。
- 反驳处理：行业分析 must-have；4 条质疑的处理结果为 2 rebutted / 2 left-open——允许且应当如实留下未解决质疑。

## 7. 操作化模式（该库固定招式）

[标注-3篇] 招式 1–4 经标注实证；[推断] 招式 5–6 仅档案散文支持。

1. **明示 N 问题清单**：开场直书"本文将解答三个问题"，后文逐题对应编号章节。
2. **信源分层标注**：官方（锚点）→ 第三方（数据）→ 社区（案例）三层显式区分；报告体以附录实体化（已核实/修订澄清/待确认三档）。
3. **判断带边界**：凡结论句带数量/范围限定（"大多数""三种""缺任意一项"），克制比 ≈ 1:3（断言型 1.05 : 限定语 3.12，统计层口径）。
4. **编号结论 + 开放问题**：收尾不收死——报告体留"后续关注问题清单"，期刊体留"局限声明+研究议程"，行业分析留"系列预告+信源征集"。
5. **单一比喻全文复用**：修路/壳/笼子式比喻服务概念而非情绪，小节结尾回收（档案 §5，待标注验证）。
6. **中英混排术语纪律**：英文原词保留，首现括注中文译名，全文唯一译名（档案 §5，统计层以 en_char_ratio 0.25 间接支持）。**英文成稿时反向适用，见 §0。**

## 8. 就绪度评估

**结论：部分能。** 统计层预算与三条已实证骨架（报告体/期刊体/行业分析）可直接指导写作；博客体/探索体骨架、论证层规范、比喻系统等仍处于单篇或零标注状态，按本 playbook 写作时须对 [推断] 与 [标注-1篇] 条目保留人工复核环节。

缺口清单：
1. 标注覆盖 3/24 篇（12.5%），博客体、探索体、blog_or_exploration 投稿类 0 标注；
2. 论证层（rubric 02）标注仅 1 篇，信源层级与证据配比系单篇外推；
3. MATTR 未入 output/kezhongke/_aggregate.json（仅档案散文与 v10 子集口径有 0.74），跨库词汇多样性比较缺统计层地基；
4. _aggregate.json 为 v0.1 口径，词表子串污染修复后 24 篇全量重跑未执行，限定语/绝对化/全称量词绝对值可能漂移；
5. blog_or_exploration 4 篇待 LLM 路由、eval-harness 两篇体裁归属待复核（档案疑指南体）；
6. emoji 红线仅档案散文，统计层无对应字段；
7. **英文口径空白**：第一输出语言已调整为英文（§0），但语料全为中文，英文成稿的定量预算（篇幅/句长/密度类）无统计层地基，当前仅结构、红线与比例类约束可执行。

最小补全动作（按性价比排序）：
1. 补标博客体、探索体各 1 篇语步（rubric 01）+ 任意 2 篇论证标注（rubric 02），使语步覆盖五体裁、论证 N≥3；
2. 24 篇 v10 口径全量重跑，刷新 _aggregate.json（含 MATTR 字段）；
3. LLM 复核 blog_or_exploration 4 篇与 eval-harness 2 篇体裁归属，更新 genre_distribution；
4. 采集壳中客英文篇目入 corpus 并重跑，补英文口径定量预算（支撑 §0 第一输出语言）。
